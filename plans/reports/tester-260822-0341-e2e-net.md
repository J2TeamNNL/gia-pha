## 2. Selector — chọn kiểu gì, vì sao bền qua đổi tên cột

Tất cả import trực tiếp `src/i18n/vi.ts` (chỉ đọc) làm nguồn chuỗi, KHÔNG hardcode lại giá trị dịch — nếu ai đổi câu chữ VI mà hành vi giữ nguyên, test tự theo:

- Onboarding/QuickAddForm: `getByRole('textbox', { name: 'Tên *', exact: true })` — accessible name suy từ `<label>` (gồm dấu `*` bắt buộc), không phải `name`/`id` HTML. Cố tình KHÔNG bao giờ điền "Họ" để tránh label đổi thành "Họ (gợi ý: …)" khi datalist xuất hiện — giữ selector ổn định.
- PersonCard: `getByRole('button', { name: /tên hiển thị/ })` — card là `<button>` chứa text tên, regex substring theo tên test tự đặt (duy nhất mỗi lần chạy nhờ `Date.now()`).
- 4 nút thêm quan hệ trên card: `getByRole('button', { name: 'Thêm cha/mẹ' | 'Thêm con' | 'Thêm vợ/chồng' | 'Thêm anh/chị/em', exact: true })` — các nút này chỉ có icon SVG, accessible name suy từ `title` attribute (đã verify hoạt động). **Ghi chú**: 4 chuỗi này hardcode tiếng Việt ngay trong `PersonCard.tsx` (không qua `t.*`) — không phải hợp đồng tôi tự đặt, là hành vi hiện tại của component (bug không theo locale đã ghi trong `CLAUDE.md`, không thuộc phạm vi tôi sửa).
- Badge vai vế ("Cha", "Con trai", "Chồng"): `getByText(..., {exact:true})` — suy ra từ `getRelationLabel()` (đọc quan hệ, không phải field tĩnh) → sống sót qua đổi `relationships`→`unions/parentages`, miễn nhãn hiển thị đúng.
- Số lượng thành viên: `getByText(/N\s*thành viên/)` — text thấy được ở badge canvas, không đọc `persons.length` qua state.
- Dialog import: `getByText(t.backup.currentTree).locator('..')` rồi `toContainText` — lấy khối `<dt>+<dd>` chứa số, không giả định cấu trúc DOM sâu hơn mức cần.
- Pan/zoom: đọc `style="transform: translate(...) scale(...)"` của layer canvas qua CSS attribute selector kết hợp 2 điều kiện (`[style*="translate("][style*="0 0"]`) để không trùng với `translate3d` của framer-motion trên các PersonCard khác. Đây là state UI cục bộ (`useState` trong `FamilyTreeCanvas`), không phải dữ liệu person/relationship — không bị ảnh hưởng bởi đổi cột DB.

Mỗi test chạy trong **BrowserContext mới của Playwright** (mặc định của `page` fixture) → IndexedDB/localStorage sạch từ đầu, không cần dọn tay.

## 3. BUG THẬT phát hiện — chặn toàn bộ luồng đọc dữ liệu trong browser

**`sql.js@1.14.0` bản browser (`sql.js/dist/sql-wasm-browser.js`, xác nhận Next/Turbopack resolve đúng file này cho client bundle qua network log: chunk `ef79e_sql_js_dist_sql-wasm-browser_*.js`) trả `db.exec()` với property `columns` bị đổi tên (minify mangling) thành `lc`** — khác với bản Node (`sql.js` main export) trả đúng `columns`.

`src/db/persons.ts` `mapRows()` destructure `const { columns, values } = result[0]` (dòng ~33-37) → `columns` = `undefined` trong browser thật → `rowToObject()` (dòng ~19-31) throw `TypeError: Cannot read properties of undefined (reading 'forEach')`.

**Hệ quả**: `getAllPersons()` và `getAllRelationships()` LUÔN throw trong browser thật (100% reproduce, 3 lần chạy full suite độc lập + 1 lần chạy debug riêng, đều cùng lỗi). `FamilyTreeCanvas.loadData()` bắt lỗi này và set `loadError` — canvas hiện màn "Không tải được cây gia phả" thay vì cây, **NGAY SAU khi tạo người đầu tiên qua onboarding**. Ghi dữ liệu (`createPerson`/`saveDb`) không bị ảnh hưởng (không đọc `.columns`), dữ liệu vẫn nằm trong IndexedDB, nhưng **không bao giờ đọc lại được qua UI**. Vì `output: "export"` build tĩnh cũng dùng chung browser bundle, đây là **bug production thật**, ảnh hưởng mọi người dùng, không chỉ dev.

### Tái hiện tối giản (không cần mở app)

```js
import initSqlJsBrowser from "sql.js/dist/sql-wasm-browser.js";
const SQL = await initSqlJsBrowser({ wasmBinary: fs.readFileSync("public/sql-wasm.wasm") });
const db = new SQL.Database();
db.run("CREATE TABLE t (id TEXT, name TEXT)");
db.run("INSERT INTO t VALUES ('1','a')");
console.log(Object.keys(db.exec("SELECT * FROM t")[0]));
// → ["lc", "values"]  (KHÔNG phải ["columns", "values"])
```
So với `import initSqlJs from "sql.js"` (bản Node/main export) trên CÙNG file wasm: trả đúng `["columns", "values"]`.

### Tái hiện trong app (Playwright, đã chạy thật)

1. Mở app (storage sạch) → điền Tên → bấm "Bắt đầu Cây Gia Phả của tôi →".
2. Ngay sau đó (không cần reload): canvas hiện "Không tải được cây gia phả — Cannot read properties of undefined (reading 'forEach')" thay vì hiện card người vừa tạo.
3. Console có đúng lỗi trên, 2 lần (React dev StrictMode double-invoke effect — cả `getAllPersons` và `getAllRelationships` đều throw).

Screenshot lỗi: `test-results/onboarding-onboarding-nhập-e70fe-ây-hiện-đúng-reload-vẫn-còn-chromium/test-failed-1.png` (còn giữ lại từ lần chạy suite, có thể xoá nếu không cần).

### Đề xuất hướng sửa (KHÔNG tự sửa — không sở hữu `src/db/**`, và đây rõ ràng là việc của agent/orchestrator đang giữ file đó)

`mapRows()`/`rowToObject()` không nên destructure cứng theo tên `columns`. Vài hướng: đọc phòng thủ (`result[0].columns ?? (result[0] as any).lc`), hoặc kiểm tra API `sql.js` có cách lấy tên cột không phụ thuộc property đã bị mangle (ví dụ qua `stmt.getColumnNames()` khi dùng `db.prepare()` thay vì `db.exec()`), hoặc ép resolve `sql.js` về bản không bị mangle cho cả Node và browser (qua alias trong bundler) — nhưng việc đó ngoài phạm vi file tôi được giao.

**Vì bug này, `pnpm test:e2e` hiện KHÔNG xanh được** — mọi luồng (2 luồng thêm người thân, chọn card, xuất/nhập, pan/zoom) đều cần canvas render được cây trước, mà canvas luôn rơi vào `loadError`. Đã báo `main` ngay khi xác nhận (§ tin nhắn cross-session) vì nó cũng chặn việc verify migration v2 của orchestrator.

3. Cô lập bằng Node script gọi trực tiếp `sql.js` main export với đúng schema/insert/select copy từ `persons.ts`/`schema.ts` hiện tại → **THÀNH CÔNG**, không lỗi. Chỉ khi ép resolve sang `sql.js/dist/sql-wasm-browser.js` (đúng file mà Next/Turbopack chọn cho browser, xác nhận qua network log) mới thấy `columns` → `lc`.
